# Handbook

Reuse the project's existing instructions and documentation first. Persist stable
invariants, architecture relationships, and terms where contributors already
look. Keep temporary task progress separate from long-lived project truth.

Create a handbook only when requested or when a concrete continuity need makes
it helpful. No .do-it tree is required to use this plugin. A small existing file
may be enough; avoid duplicating a docs/handbook or similar source.

For an explicit bootstrap request, the templates in this skill are optional
starting points. Create only useful missing files, preserve existing contents,
and explain where the project should maintain them. Do not automatically
migrate, overwrite, or remove user plans, profiles, memory, or old directories.
Use the project's format for task notes and explicit links for handoffs.
